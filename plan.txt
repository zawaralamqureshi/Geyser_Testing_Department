### 1. Goal and high‑level behavior

- **Goal**: A protocol‑aware Python tool that:
  - Reads **CLK** and **RAW** logs from `D:\Electrical_tests\Cells\` and `D:\Electrical_tests\Blocks\`.
  - **Parses program headers** (Preparation / Program / Completion) and step tags to detect which protocol is running.
  - **Ingests trusted metrics** from CLK (capacity, energy, capacitance, efficiencies, ESR, leakage, etc.).
  - **Optionally recomputes ESR** from RAW for specific protocols and delays (10 ms, 1 s).
  - Generates **curve data** (CV/SNU, Cycling V–t + I, dQ/dV).
  - Uploads to **BigQuery** on a **weekly or manual** basis via a Windows GUI.
  - Powers **Looker Studio dashboards** from BigQuery.

- **Trigger**: User runs a small **PySimpleGUI app** on the lab PC and clicks “Update BigQuery” (or uses a CLI command).

### 2. Paths, IDs, and folder flexibility

- **Primary ID & date source**: the `Object:` field and any `YYMMDD` pattern in names:
  - Example: `Object: 260210_1_B01_011_C_001` → `index_id = "260210_1_B01_011"`, date = 2026‑02‑10.
- **Fallbacks**:
  - If `Object` is generic (`Test1`, `Test2`), look for `YYMMDD` in the filename.
  - Else, fall back to `YYYY\MM\DD` from the directory tree.
- The usual structure `YYYY\MM\DD\N_Gnn\NNN\...` is **used when present** but **not required**.
  - Folders like `Blocks\2026\AGISTINE\...` or `Blocks\2026\02\10\006\Test 2\...` are handled by treating `N_Gnn`, `NNN`, `Test 2`, etc. as **metadata tags** (`batch_dir`, `group_dir`, `subtest_name`) rather than hard constraints.

### 3. Step tags and normalization

All relevant step markers from the **ASC75 manual** and your data will be mapped into canonical `step_type` values. Examples:

- **Constant‑mode steps**
  - Charge: `CHCC`, `CCC` (constant current), `CHCV` (constant voltage), `CHCP` (constant power).
  - Discharge: `DCHCC`, `DCCC`, `DCC`, `DCV`/`DCHCV`, `DCHCP`, `DCHCR`/`DCR`.
- **Scans / sweeps**
  - `SNU` (voltage scan), `SNI` (current scan), `SNP` (power scan), `SNR` (resistance scan).
- **Relaxation & logging**
  - `RLX` / `RLAX` (relaxation), `LGU` (voltage logger).
- **Table‑driven**
  - `TBU` / `Table U`, `TBI` / `Table I`, `TBP` / `Table P` / `TBLP`, `TBR` / `Table R`.
- **Pulses**
  - `IPI` (current pulse), `IPU` (voltage pulse), `IPP` (power pulse), `IPR` (resistance pulse).
- **Other**
  - `MPPT`, `Pause`, and summary `GNRL` rows.

These are normalized (e.g., to `CCC`, `DCC`, `CV_CHARGE`, `SCAN_V`, `RELAX`, `TABLE_POWER`, `PULSE_CURRENT`, etc.) so protocol detection and metric logic can work over a stable internal set, while still supporting new programs.

### 4. Protocol detection

- **Input**: parsed program header (Preparation, Program, Completion) + step markers from CLK/RAW.
- **Representation**: `ProgramStep` objects with `step_num`, `mode` (`Charge CC`, `Scanning U`, `Rest`, `Table P`, etc.), parameters, and cycle refs (`Cycle to step X N times`).
- **Matching**: a **YAML protocol registry** with patterns like:

  - `STANDARD_CELL` (SOP 3C):
    - `CCC(low)` → `SNU(up)` → `SNU(down)` → cycle SNU 3× → `CCC(high)` → `DCC` → cycle (CCC+DCC) 20× → `CCC` → `CCV` → `LGU` → `DCC`.
  - `VTT_TEST1_BLOCK` (ToS 7):
    - `CHCC(5.1V)` → `CHCV(5.1V,30s)` → `CHCC(10.2V)` → `RLAX(1s)` → `DCCC(5.1V)` → `RLAX(1s)` → 19 cycles → final `DCCC(1V)`.
  - `VTT_FCRD_NONZINC` (ToS 8):
    - `CHCC` → `CHCV` → `TBLP` → `DCCC`.
  - `CYCLABILITY` (SOP 7):
    - `CCC(1.70V)` → `DCC(0.80V)` repeated N≥1000.
  - `REFERENCE_GCD`, `DCIR_SOC`, etc.

- If no known pattern matches above a threshold, the file is labeled `UNKNOWN`; all CLK metrics are still ingested, but no protocol‑specific ESR recomputation is applied.

### 5. Metric strategy

#### 5.1 Direct ingestion from CLK (source of truth)

For each **step** and `GNRL` (cycle summary) row, ingest:

- `Q,Ah`, `E,Wh`, `C,F`, `ESR,mR`, `ERc,mR`, `ERd,mR`, `Ilk,A`, `EFq,%`, `EFe,%`, `Drt,s`,
- Plus end‑of‑step voltage/current/temperature.

We **trust these as primary metrics** across all protocols.

#### 5.2 ESR recomputation from RAW (protocol‑specific)

For selected protocols (e.g., Standard Cell, VTT Test 1):

- **Method** (per SOP 3D / ToS 7.5):

  - Locate the **discharge → rest** edge: first sample where `|I| ≤ 0.02 * I_discharge`; define that as `t=0`.
  - `VEND` = last sample with `|I| ≥ 0.98 * I_discharge`.
  - Find nearest samples at 10 ms and 1.0 s after `t=0`:
    - Strict: only if sample within `0.5 * dt`.
  - Compute `ESR10ms = (V10ms - VEND) / |I_discharge|`, `ESR1s` similarly.
  - Average over last 5 cycles if required.

- **Sampling‑rate aware**:

  - At **100 Hz** (cells) → ESR10ms and ESR1s both valid under strict rule.
  - At **10 Hz** (blocks) → ESR10ms generally **disabled** (no sample that early); ESR1s valid.
  - GUI automatically **greys out invalid delays** per file/sample rate and shows reasons.

- Config allows a **relaxed mode** (extra tolerance window) with a flag indicating `is_approximate`.

### 6. BigQuery data model

Key tables:

- `test_runs`: one row per file processed (run_id, index_id, object_id, entity_type, protocol_detected, program_text, analyzer_model, channel, sample_rate_hz, test_started, source_path, processed_at).
- `cycle_metrics`: one row per cycle per file (metrics from `GNRL` lines).
- `step_metrics`: one row per step per cycle (metrics + `step_tag`, normalized `step_type`).
- `esr_computed`: recomputed ESR values from RAW (per delay, per cycle/step; includes flags and reasons).
- `curves`: downsampled CV/SNU, Cycling, and dQ/dV curve points.

`run_id` (hash of path+size+mtime) is used to **deduplicate** on upload.

### 7. Architecture (modules)

- `config.py`: YAML config (paths, BigQuery project/dataset, ESR settings, etc.).
- `gui/app.py`: PySimpleGUI app:
  - Select folders/files.
  - Shows progress logs.
  - “Update BigQuery” button.
  - Summary of protocol coverage and data quality per run.
- `cli/main.py`: CLI equivalent for scripting.
- `parsers/header.py`: parse header (Analyzer, Object, Program, Preparation, Completion, sample rate).
- `parsers/clk_reader.py`: parse CLK metrics into cycle/step tables.
- `parsers/raw_reader.py`: stream RAW files per cycle.
- `parsers/sniffer.py`: delimiter/decimal detection (though most files are fixed‑format).
- `protocol/program_model.py`: `ProgramStep` and `ProgramDefinition` data structures.
- `protocol/detector.py`: apply registry patterns to detect protocol label.
- `protocol/registry.yaml`: extensible pattern definitions.
- `analysis/esr.py`: ESR recomputation.
- `analysis/curves.py`: generate CV/SNU, Cycling, dQ/dV curves.
- `upload/bigquery.py`: dataset/table creation, upserts, dedup.
- `upload/auth.py`: service‑account auth.
- `upload/staging.py`: local Parquet/CSV staging for offline robustness.
- `ids.py`: parse `Object` and paths into `index_id`, date, entity_type, metadata tags.
- `utils/logging.py`, `utils/errors.py`.
- `tests/`: unit tests for header parser, CLK reader, protocol detection, ESR, IDs.
- `scripts/build_exe.bat`: PyInstaller one‑file build.
- `scripts/setup_bigquery.py`: one‑time dataset/table creation.
